| Work-ledger writes are atomic and its updates serialised | PR #429 (#428 review R7) | Every update helper rewrote the whole ledger with a truncating `write_text` and no lock, so two writers in one tree lost each other's updates, and a reader that caught the truncated file got `None` and wrote a **default** ledger back. `write_ledger` now swaps a temp file in with `os.replace`, and every update holds a `flock` on `current-work.json.lock`. An update that cannot take the lock is dropped; only where nobody can lock (no `fcntl`, a filesystem without `flock`) does it run unlocked (ADR052-G4). The Stop e2e test no longer writes the live ledger. |
| Hooks act on the session's worktree, not on their own checkout | #425 (PR #428) | Claude Code desktop starts a worktree session with `--project-config-root <main>` and runs relative hook commands from there, so worktree sessions executed **main's** hook copies, and those took every root from `Path(__file__)`: main's ledger and `.claude/state`, main's tree for the ADR 054 block and the ADR 050 advisory (a worktree edit classified as `.claude/...` passed both), and main's git for the Stop hook — so the Pillar 7 Governor Footer reminder never saw worktree work, which the issue did not list. `governor.resolve_session_roots` takes the payload `cwd` to its git top-level and accepts it only for a working tree of the same repository (equal `--git-common-dir`). No `cwd` keeps the old defaults; a `cwd` it cannot place is **rejected** and callers skip session-scoped work; without git it keeps the defaults only for a `cwd` inside this checkout and outside any nested one, so a downloaded archive still works. `HARNESS_STATE_ROOT` still wins for state (#407). Codex and Antigravity are re-rooted only on the shared ledger — both already run hooks from the session's checkout (Codex docs; Gemini CLI `hookRunner.ts` spawns with `cwd: input.cwd`). `update_last_prompt` no longer stores a prompt made only of `<task-notification>` / `<system-reminder>` blocks; both were seen overwriting a live ledger. Deliberately not done: running the worktree's own hook copy, which would execute a branch's hook code — an external PR checked out for review — automatically. Takes effect only after merge **and** a pull in the main checkout, since the desktop runs main's copy. |
| Markdown links are checked, and two anchors had been dead for four months | #408 (PR #411) | The issue named three broken relative links under `docs/ai/shared/`. Sweeping the whole repository with fragments included found **thirteen in six files**, and the two the issue could not have found are the ones worth remembering: `CONTRIBUTING.md` and `docs/ai-development.md` pointed at `README.md#project-structure` and `#ai-native-development`, and **one commit killed both** — de80368, the demo-first README restructure in #79, which moved the project tree into `docs/reference.md` and renamed the other heading. Nothing noticed. That is the case for validating fragments rather than deferring them: the measurement came back the opposite way from the expectation, 2 real orphans and 0 false positives. `tools/check_doc_links.py` scans **every git-tracked `*.md` with no allow-list** — not because `docs/` is too narrow (though 150 of 646 targets live outside it) but because *a scoped path list is itself a drift generator*, which this repo has now been bitten by twice. Resolution is against the **git index**, not `Path.exists()`: macOS is case-insensitive, so `docs/History/x.md` opens locally and 404s on Linux CI. The hook **blocks**, which crosses §0's "the harness nudges" non-goal in appearance only — the discriminator this repo actually applies is *determinism*, and seven of eight local hooks already block on facts while the one advisory hook is the one asking a heuristic question. Argued in the PR rather than by ADR. Validated against the defect that motivated it: run on `adb4b57` it reports all eight #405 links that had passed three cross-tool review rounds and nine CI jobs. Fourteen review points closed, six of them from a codex round that found the checker rejecting *correct* links — setext headings, single-quoted HTML attributes, `?plain=1`, `//host/path`, backslash escapes. |
| `/fix-bug` proves the bug exists before it fixes anything | `/fix-bug` hardening | The four canonical phases are untouched (they are pinned by `target-operating-model.md` lines 22/24), but Phase 1 now **branches before any test is written**: a confirmed failure obliges a red test asserting the *specific* failure mode, a disproved causal claim exits `not-a-bug`, and anything weaker exits `cannot-reproduce` — neither exit writes production code or a test. `not-a-bug` is deliberately narrow (an authoritative contract calls the behaviour intended, or the claim is disproved in the same environment **and** code path); "I could not make it fail" is explicitly not enough, which is the #401 shape. Phase 2 adds the **Cause Impact Matrix** — candidate / reachability evidence / disposition / evidence, with a termination condition — and that is what bounds test additions to what the root cause actually reaches, replacing the open-ended "also write edge-case tests" framing the work started from. Its search procedure names **registration sets** (`Base.metadata`, `__all__`, Selector maps, registries) as a first-class axis and tells the agent to enumerate the *registrars*, not the call sites — #374's root cause was metadata completeness, which no amount of tracing the failing `drop_all` would reach. Every run emits a `Bug Fix Report` carrying **`Outcome`** (`fixed` / `partial` / `not-a-bug` / `cannot-reproduce`), deliberately **not** the review protocol's `Verdict`: ADR 053 scopes that vocabulary to the three review skills and a fourth consumer would have created a second verdict semantics. A documented Small-Bug Lane carries the common one-line bug with an explicit step-by-step delta table rather than an exception token — `[trivial]` is wrong for a behaviour bug because a regression test is required. Advisory only: no hook, no CI gate, no runtime change. |
| Harness hook tests load by path, and a guard that tested itself | #401 (PR #402) | Eight hook basenames exist in more than one harness copy (`verify_first.py` and `completion_gate.py` in all three, differing by 228 lines), so `import verify_first` names three files and `sys.modules` picks one. **The defect this was filed for did not exist**: the tier-2 tests already popped the bare key with `.claude/hooks` at `sys.path[0]`, and the third import (`user_prompt_submit`) does not collide at all because the other copies spell it with hyphens. The filing rested on reading the *end state* of `sys.modules` as what an earlier test used. What was real: that correctness came from an unstated `pop` + path pair, and the next test to omit either half would pass while exercising another harness. So the three bare imports load by path under `claude_*` / `codex_*` aliases — which tier 3 and the Codex tests in the same file already did — and an AST guard forbids the pattern, verified to fail first. **The pollution itself is unfixable from the test side**: hook files import their own siblings by bare name, correct for a standalone hook process, colliding only inside a shared pytest process. Cross-tool review then found the guard **reproduced the loading logic instead of calling it**, so a regression to a dynamic `importlib.import_module(name)` would have passed both the AST rule and the guard; it now calls the real loader and fails 3 of 5 when that regression is simulated. Two more review findings were mine: the guard mutated a `sys.modules` key it did not own without restoring, and its docstring resurrected the premise the work had disproved. |
| Typing `tests/` found six production defects | #394–#399 | The gate went from `src` + tooling to the **whole repository: 944 files, 0 errors**, and `tests/` was the last piece — 155 findings, none of them test noise. What it surfaced: a `cast(list[BaseModel], entities)` in `BaseService.create_datas` that existed **only** because `list` is invariant, deleted by widening `insert_datas` / `batch_put_items` to `Sequence[BaseModel]` (the vector store already had it); three functions asking for a class where they use one member, including an audit logger that demanded a whole repository to call `insert`; and **two doubles that had silently stopped matching the protocols they impersonate** — `MockUserRepository` missing `count_datas_by_day` since #368, `FakeUseCase` still naming a parameter `user_id` that #218 renamed to `admin_id`. Neither was catchable before: a double that no longer matches its interface still runs. `tests/support/fake_repository.py` now declares the 13-member `BaseRepositoryProtocol` surface once, every member raising, so the next protocol change breaks **one file** instead of drifting silently through N doubles. Two limits were learned by getting them wrong: a `_SupportsProps` protocol whose method signature **excluded every real `Button`** (NiceGUI's `props` is a property returning a callable wrapper), and the concrete client annotations in `ObjectStorage` / `BaseS3VectorStore` that must stay concrete because they are what type-check the boto and aiohttp calls inside them — there the double is accepted at the substitution site instead. Suppressions went 21 → 52 and the pin caught itself counting a directive quoted in **its own docstring**. |
